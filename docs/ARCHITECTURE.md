# Карта проекта

Составлена 15 ноября 2026 года по исходникам. Это описание существующей реализации,
а не план будущих изменений. При изменении архитектуры обновляйте этот файл.
Анализ выполнен чтением кода: сборка, тесты и работа с настоящим Telegram не проверялись.

## Общая идея

«Мировое господство» — помощник ведущего настольной игры. Ведущий открывает
партию на ПК или Android, игроки передают приказы через Telegram. Все правила,
расчёт хода и полное состояние партии находятся на устройстве ведущего.
Отдельного игрового сервера и базы данных нет: сохранения — JSON-файлы.

```text
Приложение ведущего (app, на ПК или Android)
  ├─ HostSession — партия, настройки, сохранения и бот
  ├─ GameController — изменение состояния и отмена
  ├─ core — проверка приказов, расчёт хода, отчёты
  └─ bot ↔ Telegram API ↔ игрок
                           └─ miniapp — HTML-форма приказов
```

Мини-приложение — отдельная статическая страница. Она получает снимок доступных
игроку данных в ссылке, а приказы возвращает через Telegram. Постоянного соединения
с приложением ведущего у страницы нет.

## Как читать пути Kotlin

`src/commonMain/kotlin/` — общий исходный код модуля; `commonTest` — его тесты.
`jvmMain` содержит реализацию для JVM, `desktopMain` — запуск на ПК.
В `app` дополнительно создан `jvmSharedMain`: файловое хранилище, общее для ПК
и Android. `androidApp/src/main/` содержит обычный Android-код и манифест.

Используется Kotlin Multiplatform и Compose Multiplatform. При этом `core` и
`bot` сейчас имеют только JVM target, который используется также Android-приложением.
Наличие `commonMain` само по себе не означает поддержку браузера или iOS.

## Ядро: `core/src/commonMain/kotlin/wd/core/`

| Файл | Что искать |
| --- | --- |
| `Model.kt` | `GameState`, страны, города, приказы, главы стран, приглашения, результат партии |
| `Rules.kt` | Цены, доходы, стартовые значения, параметры событий, масштабирование экологии по числу стран |
| `Setup.kt` | Настройка новой партии, стандартные страны, проверка названий, `newGame()` |
| `Engine.kt` | Проверка, добавление и отмена приказов; события; `resolveTurn()` |
| `Events.kt` | События рассчитанного хода и доступность событий конкретному игроку |
| `Report.kt` | Личный отчёт и разрешённые сведения о других странах |
| `Text.kt` | Русские названия, описания и значки |
| `Save.kt` | Преобразование `GameState` в JSON и обратно |

Состояние описано неизменяемыми объектами: действие возвращает новую копию
`GameState`. Очередь `pending` хранится в той же партии. При постановке приказа
деньги резервируются через `availableBalance`, фактическое списание происходит
при расчёте. Правила также входят в сохранение. Доход зависит от диапазона экологии и кризиса,
затем округляется до ближайших 5. События выбирает ведущий вручную; полный журнал
можно скопировать из панели лога.

Расчёт хода: эффект события → щиты → развитие/исследования/производство/экология
→ запуски → переводы → завершение исследований, готовые бомбы и доход
→ проверка конца игры. Возможность ответного удара сохраняется для стран,
живых перед фазой запусков. Исследование, начатое сейчас, завершается в конце
текущего хода и доступно с начала следующего; заказанные бомбы появляются в конце текущего.
После расчёта очередь и готовность очищаются, журнал пополняется, номер хода растёт.

## Приложение: `app/src/commonMain/kotlin/wd/app/`

| Файл | Ответственность |
| --- | --- |
| `App.kt` | Переключение меню, новой игры, загрузки, настроек и партии |
| `RulesScreen.kt` | Редактор всех параметров правил, сохранение шаблона и применение к партии |
| `NewGameScreen.kt` | Создание партии и выбор параметров |
| `GameScreen.kt` | Страны, города, очередь, журнал, действия ведущего; широкая и узкая компоновка |
| `GameController.kt` | Текущее состояние Compose, операции с ядром, история отмены до 100 шагов |
| `HostSession.kt` | Связь интерфейса и бота, настройки, автосохранение и запуск рассылок |
| `Storage.kt` | Интерфейс хранилища и управление именованными сохранениями |
| `BotPanel.kt` | Управление ботом и игроками в партии |
| `Console.kt` | Просмотр журнала бота |
| `Theme.kt` | Оформление и общие элементы интерфейса |

`HostSession` реализует интерфейс `GameHost` из модуля `bot`: бот может читать
партию и передавать преобразование состояния, не завися от Compose.
Операции интерфейса и бота меняют партию в главном потоке; сетевые запросы
в JVM-транспорте вынесены в IO. После изменения вызывается автосохранение.
Смена номера хода вызывает рассылку отчётов, смена события — уведомление игроков.

Отмена хранится в памяти, после перезапуска не восстанавливается. При отмене
сохраняются текущие привязки игроков и коды приглашений. Уже отправленные
сообщения Telegram не являются частью истории состояния.

`app/src/jvmSharedMain/kotlin/wd/app/FileStorage.kt` пишет JSON через временный
файл и атомарное переименование. Именованные сохранения называются «Ход N»,
автоматическое — `autosave.json`. Настройки лежат отдельно в `config/settings.json`:
токен бота, offset обработанных обновлений Telegram, адрес мини-приложения и шаблон правил для новых партий.
Токен сохраняется обычным текстом внутри JSON.

## Точки запуска и хранение

- ПК: `app/src/desktopMain/kotlin/wd/app/Main.kt`, функция `main()`.
  Создаёт `HostSession`, окно Compose и хранилища; при выходе останавливает бота.
  Консоль открывается клавишей «`» / «ё».
- Android: `androidApp/src/main/kotlin/wd/android/WdApplication.kt` создаёт
  сессию на уровне процесса приложения, `MainActivity.kt` отображает общий `App`.
  `BotService.kt` поддерживает foreground service с уведомлением при работающем боте.
  Служба сама не реализует бота и не восстанавливает всю работу после гибели процесса.

На ПК в каталоге данных `world-domination` находятся `saves/` и `config/`:
Linux — `$XDG_DATA_HOME` либо `~/.local/share`; Windows — `%APPDATA%`;
macOS — `~/Library/Application Support`. На Android — внутренний `filesDir` приложения.

## Telegram: `bot/src/`

- `commonMain/kotlin/wd/bot/GameBot.kt` — long polling, статусы связи,
  приглашения и привязки, команды и кнопки, обработка мини-приложения,
  очередь исходящих сообщений и повторы при сбоях.
- `BotText.kt` — отчёты, панели и кнопки Telegram.
- `Telegram.kt` — модели Telegram, обёртка API и интерфейс HTTP-транспорта.
- `MiniApp.kt` — упаковка снимка страны в ссылку и разбор приказов страницы.
- `jvmMain/.../UrlConnectionTransport.kt` — HTTP через Java URLConnection;
  `Time.kt` — время для журнала.

Offset сохраняется в настройках. Исходящая очередь находится в памяти экземпляра
`GameBot`: переживает его `stop/start`, но не закрытие приложения и не создание
нового экземпляра. Один токен следует запускать на одном устройстве.

## Мини-приложение: `miniapp/index.html`

Страница получает JSON в base64url из параметра `?s=`, показывает сведения о стране,
отчёты и очередь. Игрок редактирует локальный список, затем `Telegram.WebApp.sendData`
передаёт его боту. Бот определяет страну по Telegram ID отправителя, проверяет
номер хода и повторно проверяет приказы правилами ядра.

Отправленный список заменяет очередь этой страны. Неверные приказы могут быть
отклонены отдельно, а правильные приняты; игрок получает результат обработки.
Страница не обновляется в реальном времени: новое состояние приходит с новой ссылкой.
Если ссылка с отчётом превышает 2000 символов, Kotlin-код исключает отчёт из ссылки.

Часть проверок и тексты отчётов повторяются в JavaScript. При изменении приказов,
событий или их формата нужно согласованно менять `MiniApp.kt`, HTML и тесты.

### Справка для игроков

`docs/PLAYER_RULES.md` — единый текст правил для игроков. Скрипт
`scripts/build_player_rules.py` (Python Markdown + LibreOffice) создаёт
`miniapp/rules.html` и `miniapp/rules.pdf`. Кнопка «?» в `index.html` открывает HTML
в iframe внутри диалога, сохраняя текущую очередь; при открытой справке главная
кнопка Telegram скрывается, кнопка возврата закрывает справку. Страница правил
работает самостоятельно без Telegram. Обе версии публикуются вместе с miniapp.

## Сборка, тесты и публикация

Модули подключены в `settings.gradle.kts`; версии библиотек — в
`gradle/libs.versions.toml`; настройки конкретной сборки — в `*/build.gradle.kts`.
Команды запуска приведены в README. Версия установщика ПК и версия Android
заданы отдельно в `app/build.gradle.kts` и `androidApp/build.gradle.kts`.

| Проверка | Файл |
| --- | --- |
| Правила, экономика, бои, события, отчёты, JSON | `core/src/commonTest/kotlin/wd/core/EngineTest.kt` |
| Бот с поддельным HTTP: привязка, приказы, сбои сети, мини-приложение | `bot/src/commonTest/kotlin/wd/bot/GameBotTest.kt` |
| Генерация примера данных мини-приложения | `bot/src/jvmTest/kotlin/wd/bot/MiniAppSampleTest.kt` |
| Снимки экранов | `app/src/desktopTest/kotlin/wd/app/ScreenshotTest.kt` |

`.github/workflows/miniapp.yml` публикует HTML на GitHub Pages при изменении страницы
в `main`. `release.yml` по тегу `v*` собирает установщики и APK, создаёт черновик
релиза. В этих workflow нет отдельного шага запуска тестов. Android release сейчас
подписывается debug-ключом, который CI получает из секрета.

## Старый код и статус плана

`legacy/app.py` — PyQt6-интерфейс, `model.py` — данные, `engine.py` — расчёт,
`old_god.py` — более ранний вариант. Современные Kotlin-модули их не импортируют.
Автоматический перенос Python-сохранений в Kotlin этой картой не установлен.

`docs/RULES.md` описывает правила, `docs/PLAN.md` — этапы и замысел.
План не является списком ещё не сделанных задач: Android, бот, мини-приложение,
события, доклады о развитии и масштабирование экологии уже есть в исходниках.
Комментарий в `core/build.gradle.kts` про будущее добавление Android также исторический:
сейчас Android использует JVM-сборку ядра.

## Куда идти при изменениях

- Баланс игры: `Rules.kt`; порядок и ограничения действий: `Engine.kt`.
- Новое действие: модель и движок → тексты/отчёты → интерфейс ведущего → бот
  → протокол `MiniApp.kt` и JavaScript → проверки правил и обработки приказов.
- Экран ведущего: `app/commonMain`; особенности запуска: desktop `Main.kt` или Android-модуль.
- Сохранения: `Save.kt`, `Storage.kt`, `FileStorage.kt`; настройки и жизненный цикл: `HostSession.kt`.
- Ошибки связи Telegram: `GameBot.kt`, `Telegram.kt`, `UrlConnectionTransport.kt`.

## Хард-режим (добавлен 15 ноября 2026)

- `core/Hard.kt`: `GameMode`, `HardRules`, фиксированные страны, инвестиции,
  санкции, восстановление, мгновенные переводы, отдельный расчёт и итоговый рейтинг.
- `GameState.mode` по умолчанию `CLASSIC`, старые JSON читаются без миграции.
  У города добавлены `life` и `development`. Дробная экология хард-режима хранится
  в `hardEcology`; общий UI использует `ecologyValue`. Классический `ecology` остаётся целым.
- Новые приказы: `INVEST`, `REBUILD`, `SANCTION`; у `INVEST` и хард-`ECOLOGY`
  стоимость определяется `Action.amount`. Санкции адресуются через `toCountry`.
- `liveEvents` сохраняет мгновенные переводы до расчёта раунда; затем они входят
  в `TurnLog`. `processedTransfers` хранит номера выполненных запросов для защиты
  от повтора. `gameId` отличает партии с одинаковыми номерами ходов.
- `HardCountryCard.kt`, `HardRulesScreen.kt`: управление и все параметры ведущего.
  `AppSettings.defaultHardRules` — независимый шаблон; `NewGameScreen` выбирает режим.
- `bot/HardBotText.kt`: новые панели и личные отчёты. Callback-кнопки хард-режима
  содержат короткий токен партии, денежные черновики также помнят партию и раунд.
- `MiniApp.kt`: версия 2 для хард-режима. Снимок содержит `hard=true`, `g=gameId`,
  показатели и цены. Полная очередь `q` заменяется, `x=[получатель,сумма,номер]`
  выполняет отдельный мгновенный перевод, сохраняя очередь. `g` обязателен для харда.
- `miniapp/index.html` перенаправляет хард-снимок в `hard.html` с тем же параметром
  состояния. `hard.js` отвечает за отдельный UI, включая подтверждение собственного
  удара, деньги целыми числами, санкции и возврат из справки без потери очереди.
- `docs/HARD_RULES.md` → `hard-rules.html/pdf`; фазы и детали переноса описаны там.
  Источник не раскрывает серверный алгоритм полностью: порядок фаз — явно
  зафиксированное решение этой реализации, а не подтверждённая копия сервера.
- `HardTest.kt`: расчёт, восстановление, экономика, ограничения, повторы переводов,
  полная партия и JSON. Тесты бота покрывают обе версии протокола и мёртвые страны.
