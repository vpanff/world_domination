# План переработки

## Стек

Kotlin + Compose Multiplatform: одно приложение ведущего для ПК и Android.

```
core/     — правила игры без UI, сохранение в JSON
app/      — приложение ведущего (Compose): ПК + Android
bot/      — Telegram-бот (long polling внутри приложения ведущего)
miniapp/  — статическая HTML/JS-страница для игроков (GitHub Pages)
legacy/   — Python-версия 1.0.0
```

## Ключевые решения

- **Бот без сервера:** long polling, белый IP и хостинг не нужны. При обрыве сети —
  повтор с нарастающей паузой; offset обновлений сохраняется на диск. Индикатор
  связи и кнопка «перезапустить бота». На Android — foreground service.
- **Автосохранение** состояния после каждого действия.
- **Привязка игроков:** ссылка `t.me/<бот>?start=<код>` для каждой страны;
  ручной ввод Telegram ID — запасной вариант.
- **Мини-приложение:** статическая страница; состояние передаётся в ссылке
  кнопки, приказы возвращаются через `Telegram.WebApp.sendData`.
- **Личные отчёты:** каждому игроку в начале хода своя сводка (см. RULES.md).

## Ход с ботом

1. Ведущий начинает ход — бот рассылает личные отчёты.
2. Игроки ставят действия в очередь; доступный баланс уменьшается сразу,
   действия можно отменять до расчёта.
3. Ведущий видит, кто сходил, может править очередь вручную, жмёт «Завершить ход».
4. Расчёт, рассылка итогов.

## Этапы

| # | Этап | Результат |
|---|------|-----------|
| 0 | Правила | `docs/RULES.md` |
| 1 | Ядро на Kotlin | перенос model/engine, тесты, JSON, отмена действий, учёт очереди в балансе |
| 2 | ПК-приложение (MVP) | меню, создание игры с названиями, экран игры, настройки, сохранение/загрузка |
| 3 | Android | та же сборка на телефоне, автосохранение |
| 4 | Бот (текст и кнопки) | привязка, приём приказов, личные отчёты, переподключение |
| 5 | Мини-приложение | интерфейс игрока в Telegram |
| 6 | Случайные ивенты | реализация кнопки |
| 7 | Оформление | пиксельная графика, анимации, звук |
| 8 | Число игроков | баланс в зависимости от количества стран |
